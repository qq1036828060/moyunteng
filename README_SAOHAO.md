# saohao 分支后端开发说明

## 实例位并发锁

- 支付扫码任务按 `主机ID + 实例位` 获取数据库原子锁，同一实例位同时只能执行一个控制任务。
- 锁覆盖容器准备、二维码上传、虚拟摄像头设置和全部坐标点击步骤。
- 并发请求获取锁失败时返回“当前云机正在执行其他任务，请稍后重试”，不会覆盖正在执行的二维码或点击流程。
- 任务完成或异常时按锁持有者在 `finally` 中释放；锁最长保留 120 秒，服务异常退出后可自动恢复。
- 锁复用 `cloud_container.lock_owner` 和 `lock_expire_time` 字段，不需要新增数据库结构。

`saohao` 是在原有云机主机、容器同步和 Android API 能力基础上建立的独立业务分支。
当前阶段只开发后端，复用主机管理与同步能力，并新增用户支付宝扫码支付操作接口。

## 当前业务约束

- 一个主机包含多个实例位。
- 一个实例位同一时间只允许一个云机运行。
- 一个实例位只能分配给一个用户。
- 用户接口只允许操作当前登录用户已分配的云机。
- 支付密码只用于本次坐标点击，不保存到数据库、不写入操作日志、不在响应中返回。

## 支付扫码接口

```text
POST /cloud/saohao/pay/scan
Content-Type: multipart/form-data
Permission: cloud:mycontainer:operate
```

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 支付二维码图片 |
| `payPassword` | 是 | 6 位数字支付密码，例如 `112233` |
| `containerId` | 否 | 指定当前用户的云机；用户只有一个实例位时可省略 |
| `filePath` | 否 | 前端上传图片的来源地址，仅用于结果记录 |

未传 `containerId` 时，后端查询当前用户分配的实例位。未分配时拒绝操作；分配多个实例位时要求明确传入 `containerId`。

## 执行流程

1. 校验当前登录用户和云机归属。
2. 同步目标主机运行状态，关闭同实例位其他运行云机，并启动目标云机。
3. 通过 Android API `/upload` 覆盖上传二维码，资源路径使用 `/upload/{文件名}`。
4. 调用 `modifydev?cmd=4&type=image` 设置虚拟摄像头图片源。
5. 调用 `camera?cmd=start` 启动虚拟摄像头。
6. 打开支付宝 `com.eg.android.AlipayGphone`。
7. 按参考图坐标点击“扫一扫”和“极速付款”。
8. 按密码数字顺序点击支付密码键盘。

## 坐标基准

坐标基于 `720 x 1280` 参考图片，执行时按云机实际宽高等比例换算：

- 扫一扫：`(90, 214)`
- 极速付款：`(360, 1150)`
- 数字 1/2/3：`(120,875)`、`(360,875)`、`(600,875)`
- 数字 4/5/6：`(120,991)`、`(360,991)`、`(600,991)`
- 数字 7/8/9：`(120,1108)`、`(360,1108)`、`(600,1108)`
- 数字 0：`(360,1223)`

例如密码 `112233` 会依次点击数字 1 两次、数字 2 两次、数字 3 两次。

## 银行卡支付接口

银行卡支付拆分为发起支付和提交短信验证码两个接口。当前业务账号有且只绑定一张银行卡，`/bank` 不接收银行卡名称、卡号、尾号等识别文本，进入支付方式列表后固定选择第一张卡。

### 发起银行卡支付

```text
POST /cloud/saohao/pay/bank
Content-Type: application/json
Permission: cloud:mycontainer:operate
```

请求体：

```json
{
  "containerId": 100
}
```

`containerId` 可选；当前用户只有一个已分配实例位时可传空对象 `{}`。接口准备用户云机后，依次点击两次“待付款”、下拉刷新、进入第一笔待付款订单、展开其他支付方式、选择第一张银行卡、点击立即支付并获取验证码。成功后返回 `taskId` 和状态 `WAITING_BANK_CODE`。

### 提交短信验证码

```text
POST /cloud/saohao/pay/bankcode
Content-Type: application/json
Permission: cloud:mycontainer:operate
```

请求体：

```json
{
  "taskId": "第一阶段返回的UUID",
  "code": "090211"
}
```

验证码必须为 4 至 8 位数字。后端使用 `taskId` 接管第一阶段持有的实例位锁，点击验证码输入框，通过 Android shell 输入验证码，再根据实时 UI 层级定位“确认支付”按钮。成功下发后返回状态 `SUBMITTED` 并释放锁。

### 并发与超时

- `/bank` 成功请求验证码后保留实例位锁 600 秒，等待 `/bankcode` 继续任务。
- 同一实例位在等待验证码期间不能执行扫码、另一笔银行卡支付或其他受锁保护的任务。
- `/bankcode` 使用数据库条件更新原子接管锁；同一 `taskId` 的并发或重复提交只有一次能够执行。
- 第一阶段异常、第二阶段完成或异常时主动释放锁；服务异常退出时由锁到期时间自动恢复。
- 银行卡支付请求和验证码请求均关闭操作日志请求体记录，验证码不保存到数据库。
